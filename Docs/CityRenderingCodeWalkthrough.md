# City Rendering Code Walkthrough

This document explains `ASimCity2000CityActor` and its helper code. The actor is the main place where the remake turns decoded `.sc2` city data, SimCopter `GEO/*.MAX` meshes, and Maxis bitmap atlases into an Unreal scene.

The actor is also where many decompilation findings become executable behavior:

- `FUN_0047c0c0`: original city mesh builder and bridge/road object dispatch.
- `FUN_00470571`: original globally-unique object-id lookup.
- `FUN_004abc20`: original ALTM height helper.
- `FUN_004abce0`: original terrain height/type grid builder.
- `FUN_004814c0`: terrain rendering path that consumes terrain type codes.

## High-Level Pipeline

`RebuildCity` performs one full build:

1. Clear old components, debug counters, transient textures, and dynamic materials.
2. Resolve and parse the configured `.sc2` city file with `FSimCity2000Reader`.
3. Load baked generated atlas materials if they exist under `/Game/Generated/CityAtlas`.
4. Load the original mesh packs when original meshes or runtime texture decoding need the shared palette.
5. Optionally decode runtime fallback textures from `SIM3D.BMP`, `SKY.BMP`, and `TILED1.BMP`.
6. Build the SimCopter terrain type grid from SC2 layers.
7. Optionally generate procedural terrain outside the 128x128 original city.
8. Loop every city tile and append terrain quads (land, and water into its own section) plus original meshes.
9. Build extension terrain outside the original map.
10. Commit terrain sections to `TerrainMeshComponent` (land low/high pages, plus the animated water section).
11. Commit palette and textured mesh sections to `OriginalMeshComponent`.
12. Log counts that can be compared across rebuilds.

The committed city path is the generated terrain mesh plus the original mesh component. The old `TerrainInstances`/`WaterInstances`/`RoadInstances`/`BuildingInstances` HISM fallback/placeholder components were removed; tiles whose original mesh does not resolve (currently the flat-road variants XBLD `0x3b`–`0x3e`) simply render bare terrain plus road markings instead of a gray placeholder box. Water terrain tiles are committed to a dedicated `TerrainMeshComponent` section drawn with the `M_SimCopterWater` material, which undulates the surface vertically in the vertex shader (World Position Offset) with analytic wave normals - GPU-only, so it animates in the editor and in game with no per-frame CPU cost. A per-vertex shoreline weight is baked into vertex-color R (0 = pinned to land, 1 = open water) so the sea stays welded to the static land (see `Docs/ReverseEngineering.md`).

`bSmoothTerrainShading` (default on) welds the natural land terrain's per-tile flat normals into averaged smooth corner normals so hills shade smoothly instead of blocky, matching the water. Both land atlas sections (low/high page) are welded together by corner position so there is no shading seam between them, and per-tile "clamp" flags keep the terrain under buildings/roads flat (`bRoadLikeTile || bBuildingLikeTile`) so those conditioned flat pads stay crisp. Man-made face normals still contribute to a natural neighbour's average, so the ground eases up to a pad rather than creasing. `AccumulateTerrainCornerNormals`/`ApplySmoothTerrainNormals` do the weld; it is a one-time build cost with no runtime component. The water section is welded into the same pass so its rest normal is continuous with the land at the shoreline.

`bEnableTerrainDetailNoise` (default on) draws the ground with `M_SimCopterTerrain` instead of the plain baked terrain material, perturbing the shading normal with three configurable octaves of procedural noise for subtle relief. A per-vertex detail weight is baked into the land vertex colors' R channel: 0 at corners touching water (ramping to 1 over `TerrainNoiseWaterFadeTiles`) and 0 on building/road tiles, so the noise never disturbs the shoreline weld or the flat pads. `LandCornerDetailWeight` computes it (mirror of the water shore ramp, from the land side).

## Local Types

`FOriginalMeshSectionData` stores one render section before it is submitted to a `UProceduralMeshComponent`.

- `Vertices`, `Triangles`, `Normals`, `UVs`, `VertexColors`, and `Tangents` match Unreal procedural mesh section inputs.
- `UV1` is only populated for baked page-atlas city materials. It stores the atlas cell column/row for `M_SimCopterCityAtlas`.
- `TriangleCount` is a cheap per-section diagnostic.

`FBakedCityAtlasMaterials` stores optional saved material instances generated by `Tools/Unreal/BakeCityAtlas.py`.

- `PageMaterials` are full 8x8 page-atlas materials, keyed by original texture page id.
- `DirectImageMaterials` are direct image materials for rare face type `13` paths.
- `TerrainLowMaterial` is the generated material for `TILED1.BMP`.
- `TerrainHighMaterial` is the generated material for `SIM3D.BMP` image `13`, used by high terrain type codes.
- `NumLoadedMaterials` reports a combined count for debug logging.

`FTileFootprint` explains whether an SC2 tile should render an original mesh.

- `bShouldRender` false means this tile is a child of a multi-tile building.
- `bSuppressedChildTile` tells placeholder code not to fill suppressed child tiles.
- `Width` and `Height` center the original mesh across a multi-tile footprint.

`FOriginalBridgeDispatch` stores one or two globally unique mesh object ids selected by the original city builder.

`FExtendedTerrainData` stores the optional generated terrain around the original 128x128 city.

- `ExtensionTiles` is the requested border width.
- `MinTileCoordinate` is negative when an extension exists.
- `TileGridSize` is `128 + ExtensionTiles * 2`.
- `GridVertexZ` stores grid-corner heights for the expanded terrain.
- `TerrainTypes` stores SimCopter-style terrain type codes.
- `WaterMask` marks generated water tiles.
- The small member functions are bounds/index helpers so loops do not repeat coordinate math.

## Texture Helpers

`ResolveMaxisFaceColor` returns a palette color for non-textured faces, a fallback color for textured face types `13` and `18`, or white when no palette entry is available.

`IsTexturedMaxisFace` centralizes the current textured face types: `13` and `18`.

`MakeMaxisTextureKey` combines original texture file/page id and texture number into one integer key: high byte is texture file, low byte is texture number.

`GetMaxisFaceTextureKey` maps face type `13` to direct image key `(0, MaterialIndex)` and face type `18` to atlas cell key `(TextureAtlasIndex, MaterialIndex)`. Other face types return `INDEX_NONE`.

`CreateTextureFromMaxisImage` creates a transient `UTexture2D` from decoded RGBA pixels. It validates dimensions, creates a nearest-filtered wrapping texture, disables mip generation in editor-only data, copies pixels into mip bulk data, and calls `UpdateResource`.

`AddOriginalTexture` avoids duplicate transient texture creation, creates the texture, stores it in the actor-owned cache so GC keeps it alive, and records the key as available.

`AddAtlasTiles` slices every 32x32 cell from a decoded 8-column atlas page and registers each cell under `MakeMaxisTextureKey(TextureFile, TileIndex)`.

`MakeBakedAtlasPageSectionKey` and `MakeBakedDirectImageSectionKey` add high-bit flags to section keys so baked material sections cannot collide with runtime texture keys or the palette section.

`IsBakedAtlasPageSectionKey`, `IsBakedDirectImageSectionKey`, and `GetBakedSectionAssetIndex` decode those flagged section keys.

`LoadGeneratedCityAtlasMaterial` checks whether a generated material package exists before loading it. This prevents noisy load failures when the user has not baked local original art yet.

`LoadBakedCityAtlasMaterials` scans possible asset indexes `0..255` for generated city page and direct image materials, then loads the two named terrain materials.

`CreateOriginalMeshSection` submits one `FOriginalMeshSectionData` to `UProceduralMeshComponent`. When `UV1` matches the vertex count it uses the overload that supplies UV channels 0..3; otherwise it uses the simpler single-UV overload.

## Coordinate and Height Helpers

`GetWorldGridCoordinate` converts a file grid-line coordinate into centered world space: `FileCoordinate * TileSize - HalfMapSize`.

`GetWorldTileCenterCoordinate` converts a file tile coordinate into centered world space by adding `0.5` before scaling.

`GetOriginalTerrainHeightStep` mirrors the original height helper: use secondary altitude only when it is higher than base altitude and the terrain code is water/shore-like (`XTER > 0x0f`).

`GetTerrainSurfaceZ` adds a tunnel offset for terrain codes `0x0d` and `0x0e`, adds the original `+1` height step, and converts steps to Unreal Z with `TerrainHeightScale`.

`GetTerrainTileCenterZ` bounds-checks file coordinates and returns center height for a tile.

`GetTerrainGridVertexZ` approximates the original `tmap` grid-corner pass by averaging up to four surrounding tile-center heights.

`GetAverageTerrainSurfaceZ` averages center heights over a multi-tile footprint, used to place large building meshes.

`GetMaxisTerrainAtlasCellUV` converts a SimCopter terrain type cell into UVs for the decoded Unreal texture layout. It clamps to `0..63`, derives 8-column atlas column and raw row, mirrors the row because `FMaxisTextureReader` already flipped composite bitmap rows, and insets UVs by half a pixel to avoid bleeding.

`GetTerrainHeightMapSample`, `GetTerrainTileCenterHeightMapSample`, and `GetTerrainGridHeightMapSample` mirror the integer `tmap` height samples used by decompiled flat/sloped tests. These use `(height + tunnel + 1) * 0x20`, matching the original scale before Unreal centimeters.

`GetTerrainTileAverageHeightMapSample` averages the four integer grid-corner samples for terrain-band decisions.

`IsOriginalTerrainTileFlat` returns true only when all four integer grid-corner height samples match. The bridge/road dispatch uses this to select flat or sloped mesh object ids.

## Bridge and Elevated Road Dispatch

`GetOriginalBridgeDispatch` is transcribed from original city builder switch cases for `XBLD 0x3f..0x6b`.

Important rules:

- It returns globally unique object ids, not GEOM table indexes.
- Object ids are resolved through `FMaxisMeshLibrary::FindObjectByObjectId`.
- `0x43..0x46` use `IsOriginalTerrainTileFlat` to choose flat versus sloped primary meshes.
- `0x45`, `0x46`, `0x4d`, and `0x4e` add secondary side objects.
- Several ids add `BitVariant`, derived from `XBIT & 0x02`, to choose paired `F` variants.

This matters because the public `XBLD` heuristic table is not sufficient for bridges. Orientation is baked into object choice, so a wrong object id can look like a rotation bug.

## Road Markings

The original software renderer drew some road details as vector-thin line primitives. The remake restores the missing road-center markings as raised procedural quads in a separate non-colliding `RoadMarkingMeshComponent`. The road id is decoded through the original road-opening family for surface road ids `RD29..RD38` (`XBLD 0x1d..0x26`), linear ramp/crossing ids `0x3f..0x46`, and the simple `RD73`/`RD74` bridge-road ids (`0x49`, `0x4a`, `0x4d`, `0x4e`, `0x4f`, `0x50`). Only two-opening tiles draw a marking, while T-junctions and the four-way intersection intentionally draw none. Straight tiles use two centered dash segments and diagonal tiles use one centered dash segment. The dash period is tile-local with equal half-gaps at tile edges, so adjacent tiles create a normal dash gap without letting the marking geometry connect across the boundary.

## Building Base Dispatch

`GetOriginalBuildingDispatch` is transcribed from the `XBLD 0x70..0xff` half of `FUN_0047c0c0`. Building primary meshes now resolve by original runtime object id through `FUN_00470571` semantics, instead of relying on the public heuristic `XBLD` mapping table. Most building switch cases `break` into the original shared tail, which calls `FUN_00482890` and creates a secondary base/foundation object (`local_2c = 2`). Only the cases that jump directly to `LAB_0047f179` with `local_2c = 1`, or cases with explicit fixed secondary objects, bypass that default base behavior. `FUN_00482890` chooses its base from `XZON & 0x0f` and the original footprint-size table from `FUN_004e4f80`.

The `0xdd` and `0xdf` branches compare whether `XBIT & 0x02` is clear against `DAT_004fa9e0 & 1`; `DAT_004fa9e0` is loaded from `MISC` dword offset `0x0008`, the saved rotation field already exposed as `City.Rotation`. The special one-time `0xe7` branch is represented with a local per-rebuild flag, matching the city-builder sweep behavior.

## Deterministic Terrain Noise

The original game uses clock-seeded MSVCRT randomness for some terrain detail passes. The remake currently keeps the same candidate sets and probabilities, but uses stable hash noise so editor rebuilds are deterministic.

`HashTerrainTile` hashes X, Y, and a salt through integer mixing.

`HashUnitFloat` turns the low 24 hash bits into `0..1`.

`SmoothNoise2D` samples four lattice hash values and smoothsteps the fractional coordinate.

`FractalNoise2D` combines low, mid, and high frequency noise. It is used for generated map-extension terrain, not for original SC2 tile decoding.

`GetTerrainTypeBase` maps detail variants back to their base terrain band:

- `0..9` become water base `5`.
- `0x70..0x72` become `0x10`.
- `0x73..0x75` become `0x20`.
- `0x76..0x78` become `0x30`.
- `0x79..0x7b` become `0x40`.
- `0x7c..0x7e` become `0x60`.
- Otherwise the high nibble is used.

`IsWaterTerrainBase`, `GetLandBandIndex`, and `GetLandBaseTypeFromBand` provide small classification utilities for terrain bands.

`GetDistanceOutsideOriginalMap` and `GetDistanceOutsideOriginalGrid` compute how far a tile or grid vertex lies outside the 128x128 original city.

`Smooth01` is the standard `t*t*(3-2*t)` smoothing curve used by terrain blending.

## Boundary Sampling for Map Extension

The generated outer terrain tries to continue the original city edges instead of surrounding every city with the same generic terrain.

`EBoundarySide` names the edge sampled: top, bottom, left, or right.

`FBoundaryProfile` accumulates landness, terrain band, height, and total weight.

`AddBoundaryProfile` samples a weighted strip of original edge tiles near the projected outside coordinate. Noise warps the along-edge coordinate slightly, then nearby edge samples contribute land/water, land band, and height.

`NormalizeBoundaryProfile` divides accumulated values by weight or supplies a neutral fallback if no samples were accumulated.

`SampleOutsideTileBoundaryProfile` samples whichever original edge or edges an outside tile lies beyond. Corner tiles can accumulate from two sides.

`SampleOutsideGridBoundaryProfile` is the grid-vertex equivalent.

`GetBoundaryConstraint` computes how strongly generated terrain should honor the original boundary. Water-heavy edges persist farther outward.

## Terrain Type Grid

`ResolveOriginalTerrainDetailType` reproduces the final random detail step from `FUN_004abce0`:

- Only exact base cells `0x10`, `0x20`, `0x30`, `0x40`, and `0x60` can get detail variants.
- `0x50` and transition-masked cells are skipped.
- A first random draw gates detail.
- A second random draw chooses one of three variants.
- The remake uses hash draws instead of clock-seeded `rand()`.

`BuildTerrainTextureTypeGrid` reconstructs the original 128x128 terrain type grid:

1. Allocate one byte per city tile.
2. Measure min/max original height-map samples.
3. Define local lambdas for neighbor inspection.
4. Classify initial tile type:
   - default `0x30` inland grass.
   - `XTER > 0x0f` becomes water type `5`.
   - `XBLD 0xf8` becomes shore/low type `0x10`.
   - `XBLD 6..0x0d`, `0xd5`, or `0xda` becomes wooded/feature ground `0x20`.
   - `XBLD 1..4` becomes deterministic `10` or `11`, matching the original random water-feature branch.
5. Convert land/near-shore next to water into shore `0x10`.
6. Convert grass next to shore into near-shore `0x20`.
7. Convert water next to land into coastal water `0`.
8. Promote/demote natural land through height bands `0x10..0x60`.
9. Apply directional transition masks where a neighbor is in the next lower band. The bits preserve the original `DAT_005bde80` addressing meaning: north `1`, east `2`, south `4`, west `8`.
10. Apply the deterministic detail pass.

The returned byte value is also the atlas cell index for low terrain page `0x14` (`TILED1.BMP`) unless it is `>= 0x40`, in which case the high terrain page `0x0d` uses `type - 0x40`.

## Procedural Map Extension

`BuildProceduralExtendedTerrain` is not known original executable logic. It is a remake convenience layer that creates readable terrain beyond the original city boundary while preserving SimCopter terrain type semantics.

Key phases:

1. Clamp extension size and allocate expanded arrays.
2. Copy original map terrain types and water mask into the expanded coordinate space.
3. Estimate ocean surface height from water tiles, falling back to minimum original grid height.
4. Generate land/water outside the map by blending noise with boundary profiles.
5. Assign generated land to base terrain bands.
6. Force near-water land to low bands for coast shape.
7. Smooth land bands over three passes so neighboring bands do not jump too sharply.
8. Mark generated water as coastal water `0` when it touches land, otherwise open water `5`.
9. Apply the same transition-mask convention as the original grid.
10. Apply deterministic detail variants.
11. Copy original grid-corner heights.
12. Generate outside grid-corner heights from neighboring water/land context, boundary profiles, and noise.

Because it preserves SimCopter terrain type ranges, the renderer can use the same terrain atlas logic for original and generated tiles.

## Terrain Mesh Assembly

`AppendTerrainTileWithHeights` emits one quad into a terrain section:

- The four vertices are placed at grid corners.
- File Y is negated for world Y to match the city grid mapping.
- UVs use `GetMaxisTerrainAtlasCellUV` with local corners.
- Normals use swapped cross-product operands because the world-Y negation mirrors the quad winding.
- Two triangles are emitted.

`AppendTerrainTile` is the city-data wrapper that samples four grid-corner heights before calling `AppendTerrainTileWithHeights`.

## Building Footprints

`FSimCopterCityGeometryRules::ClaimOriginalBuildingFootprint` mirrors the scene-cell claim in
`FUN_0047c0c0`:

- `FUN_004e4f80` supplies one square size (1-4 tiles) from the building's `XBLD` id.
- The full square must be inside the map and every cell must carry that same `XBLD` id.
- The first valid cell in the row-major sweep claims the square; later covered cells are suppressed.
- The mesh origin is the center of that claimed square.
- `XZON` is deliberately not consulted. Its corner markers are SimCity zone data, not SimCopter's
  building-mesh owner field.

The old `XZON & 0x80` path selected the far corner of many Islandtown footprints and then failed to
find its right/down endpoints, so it centered 2x2-4x4 GEO models as 1x1 objects over neighboring
roads.

## Original Mesh Assembly

`AppendMaxisMeshObject` appends one decoded Maxis object at one tile origin:

1. Compute the object centroid in the same converted/scaled/local-yawed space used by emitted vertices.
2. Skip faces with fewer than three indices.
3. Decide whether a face is baked-page textured, baked-direct textured, runtime textured, or palette/fallback colored.
4. Choose a section key:
   - baked atlas page flag plus texture page id,
   - baked direct image flag plus image id,
   - runtime texture key,
   - or `INDEX_NONE` for palette/fallback.
5. Convert each valid source vertex through `FMaxisMeshReader::ConvertMaxisVertexToUnreal`.
6. Apply the global 180-degree yaw by negating local X and Y.
7. Add the tile origin.
8. Convert raw UVs when available.
9. Add `UV1` atlas cell data for baked atlas page faces.
10. Roll back partial face output if fewer than three valid vertices were emitted.
11. Compute a winding-derived normal.
12. Flip the normal outward from the object centroid when needed.
13. Triangulate the face as a fan.
14. Optionally add reversed backface triangles.
15. Count total and textured triangles.

The crucial fidelity point is that the function does not rotate individual road/building tiles. The original builder chose pre-oriented meshes, and the remake follows that rule.

## Actor Construction

`ASimCity2000CityActor::ASimCity2000CityActor` creates all components and default assets:

- Disables ticking because city geometry is rebuilt explicitly.
- Creates `SceneRoot`.
- Creates fallback HISM components for terrain, water, roads, and buildings.
- Creates procedural mesh components for terrain and original meshes.
- Configures procedural mesh collision as world static, complex-as-simple, and non-navigation-affecting.
- Loads the engine cube and basic material for placeholders.
- Loads project-authored lit vertex-color and lit texture materials.
- Configures instance components.
- Defaults `CityFile` to `../Reference/SimCopterOriginalGame/cities/Demo.sc2`.
- Defaults `OriginalGameRoot` to `../Reference/SimCopterOriginalGame`.

`OnConstruction` calls `RebuildCity` when `bLoadOnConstruction` is true.

`BeginPlay` calls `RebuildCity` when `bLoadOnBeginPlay` is true.

## RebuildCity Detailed Walkthrough

`RebuildCity` starts by clearing state:

- Reset the last error/name/counters.
- Drop transient textures and dynamic materials.
- Clear all instances and mesh sections.
- Reapply component configuration and collision toggles.
- Reapply placeholder materials.
- Reset the original mesh component material to the vertex-color material.

It then resolves and parses the city:

- Empty city path is a recoverable warning.
- `FSimCity2000Reader::LoadCityFromFile` does all binary validation.
- `LastLoadedCityName` records the parsed city name.

It prepares original assets:

- Baked atlas materials are preferred when `bRenderOriginalTextures` is true.
- Available baked page/direct image ids are copied into sets for quick face routing.
- Runtime texture decoding is only needed when baked materials are incomplete or terrain baked materials are missing.
- Mesh library loading is needed for original meshes or for the shared palette required by runtime texture decoding.
- `SIM3D.BMP` is decoded for direct images, atlas pages, and high terrain image `13`.
- `SKY.BMP` image `4` is decoded as special texture file/page `20`.
- `TILED1.BMP` image `0` is decoded as the low terrain atlas when baked terrain is absent.

It computes scale and section state:

- `HalfMapSize = 128 * TileSize * 0.5`.
- Placeholder cube scale converts centimeters to Unreal cube scale with `1/100`.
- Original mesh scale is `TileSize / OriginalMeshSourceTileSize`.
- Effective terrain height scale is either `TileSize * 0.5` or the editable `TerrainHeightScale`.
- Separate terrain sections are kept for low page `0x14` and high page `0x0d`.

It builds the original map:

- Loop order is file rows (`FileY`) outside, columns (`FileX`) inside.
- `TileIndex` is `FileY * 128 + FileX`.
- World mapping uses `WorldX = center(FileX)` and `WorldY = -center(FileY)`.
- Terrain always appends one quad when `bRenderTerrain` is true.
- Water placeholder plates only render when there is no textured terrain surface.
- Original mesh placement only attempts road-like/building-like `XBLD` ids.
- Building footprints can suppress child tiles.
- Bridge/elevated-road `0x3f..0x6b` use exact object-id dispatch.
- Other tiles use the heuristic tile-id mesh library.
- Secondary bridge objects are appended at the same tile origin.
- Missing original meshes increment diagnostics and may fall back to placeholders.
- Road and building placeholders render only when original mesh rendering was not attempted or failed and fallback is enabled.

It builds extension terrain:

- Skips the original 128x128 map area.
- Uses extended terrain type codes and generated grid heights.
- Uses the same low/high terrain page split.
- Adds fallback water plates for generated water only when textured terrain is absent.

It commits terrain sections:

- A local lambda creates each procedural terrain section.
- Baked terrain material wins.
- Runtime transient texture plus `TexturedMaterial` is fallback.
- Vertex-color material is last fallback.

It commits original mesh sections:

- Palette/fallback section `INDEX_NONE` is created first and uses the vertex-color material.
- Textured section keys are sorted for deterministic material section order.
- Baked page/direct materials win.
- Runtime transient textures use dynamic material instances.
- Sections without any usable material are skipped rather than rendering with a misleading material.

Finally, it records `LastOriginalMeshTriangleCount` and logs a full render summary.

## Public Accessors

`GetResolvedCityPath`, `GetResolvedOriginalGameRoot`, `GetTileSize`, `UsesOriginalTerrainHeightScale`, `GetTerrainHeightScale`, and `GetEffectiveTerrainHeightScale` expose the city actor as a source of truth for other systems such as traffic and population.

`ResolveCityPath` and `ResolveOriginalGameRoot` trim empty paths, resolve relative paths against `FPaths::ProjectDir()`, and normalize absolute paths.

## Placeholder Helpers

`ConfigureInstanceComponent` assigns the shared cube mesh, collision mode, world-static collision profile, no navigation contribution, and no shadows to fallback HISM components.

`ApplyComponentMaterial` creates a dynamic instance of the shared basic material and sets both `Color` and `BaseColor` to cover material parameter naming differences.

`IsRoadLikeTile` currently treats `XBLD 0x0e..0x6f` as road/infrastructure. This includes power, road, rail, bridge, and related non-building city pieces.

`IsBuildingLikeTile` treats `XBLD >= 0x70` as buildings.

`EstimateBuildingFloors` is placeholder-only height massing. It is not original mesh behavior; it exists so missing original building meshes still create useful debug volumes.

## Current Fidelity Notes

- Per-tile mesh rotation is intentionally absent. Orientation is encoded by mesh object choice.
- The city placement uses a Y-axis sign correction and global yaw to line up with decompiled world coordinates and the current Unreal scene orientation.
- Terrain texture selection comes from reconstructed terrain type codes, not direct `XTER` lookup.
- Baked city atlas materials are preferred because transient runtime textures can be lost or regenerated during editor/PIE lifecycle.
- Generated map extension is a remake addition. It should not be cited as original behavior, even though it reuses original terrain type conventions.
